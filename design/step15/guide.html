Declare schemas

A Schemas class tells the framework which fields each operation reads and writes. It is the same on a ModelSerializer and on a Serializer for a model you already have.

Before you start You have a model and an APIViewSet from the Quickstart.

The four schema kinds

Each kind maps to one part of the HTTP contract. Declare only the ones you need.

KindUsed forIf omitted
createPOST request bodyCreate endpoint is not generated
updatePATCH request bodyUpdate endpoint is not generated
readList items and write responsesRead endpoints are not generated
detailGET /{id} responseReuses read

Declare them

Pick the tab for your serializer style. Everything after the Schemas class, including viewsets and OpenAPI, is identical for both.

blog/models.py 
from django.db import models
from ninja_aio import ModelSerializer, SchemaConfig


class Article(ModelSerializer):
    title = models.CharField(max_length=200)
    body = models.TextField()
    is_published = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)

    class Schemas:
        create = SchemaConfig(
            fields=["title", "body"],
            optionals=[("is_published", bool)],
        )
        update = SchemaConfig(
            optionals=[("title", str), ("body", str), ("is_published", bool)],
        )
        read = SchemaConfig(
            fields=["id", "title", "is_published", "created_at"],
        )
        # detail omitted: retrieve reuses read
from ninja_aio import Serializer, SchemaConfig

from blog.models import Article  # an existing models.Model


class ArticleSerializer(Serializer[Article]):
    class Meta:
        model = Article

    class Schemas:
        create = SchemaConfig(
            fields=["title", "body"],
            optionals=[("is_published", bool)],
        )
        update = SchemaConfig(
            optionals=[("title", str), ("body", str), ("is_published", bool)],
        )
        read = SchemaConfig(
            fields=["id", "title", "is_published", "created_at"],
        )

SchemaConfig options

OptionKindsWhat it does
fieldsallModel fields to include. Required on create.
optionalsall(name, type) pairs accepted but not required.
customsallFields that are not model columns: (name, type) or (name, type, default).
excludesallFields removed from the generated schema.
relations_as_idread, detailSerialize these relations as their primary key.
nestedcreateReverse-FK children created with the parent. ModelSerializer only.
model_configallPydantic ConfigDict for the generated schema.

Use a generated schema

Schemas are class attributes. They are built on first access and cached, so reading one in a route signature costs nothing after startup.

blog/api.py 
@api.get("/featured-articles", response=list[Article.read_schema])
def featured(request):
    articles = Article.get_queryset(request=request).filter(is_published=True)[:3]
    return Article.model_dumps(articles)

# Deeper nesting for one route only
ArticleTree = Article.get_schema("read", depth=2)

Startup checks

Mistakes in Schemas surface when Django starts, not on the first request.

ninja_aio.E001Unknown schema kind
ninja_aio.E002Value is not a SchemaConfig
ninja_aio.E003Unknown field name
ninja_aio.E004Field in both fields and optionals
ninja_aio.E005relations_as_id or nested on an unsupported kind
ninja_aio.E006relations_as_id entry is not a relation

Coming from version 2

Deprecated in 3.0, removed in 4.0

CreateSerializer, ReadSerializer, UpdateSerializer, DetailSerializer and Meta.schema_in/schema_out still work and emit a DeprecationWarning. Declaring them next to Schemas raises ImproperlyConfigured. Migration: deprecations
